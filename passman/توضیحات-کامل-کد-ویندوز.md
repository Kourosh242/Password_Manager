## ۴. `main.js` — پروسهٔ اصلی

### ۴.۱ تک‌نمونه‌ای (Single Instance)
```js
const gotLock = app.requestSingleInstanceLock();
if (!gotLock) { app.quit(); } else {
  app.on('second-instance', () => { /* پنجرهٔ موجود را جلو بیاور */ });
}
```

### ۴.۲ ساخت پنجره
```js
new BrowserWindow({
  width: 1140, height: 760, minWidth: 400, minHeight: 560,
  icon: resources/icon.png,
  show: false,                       // تا آماده‌شدن رندر پنهان
  webPreferences: {
    preload: 'preload.js',
    contextIsolation: true,          // جداسازی کامل کانتکست
    nodeIntegration: false,          // صفحه به Node دسترسی ندارد
    sandbox: true,
    spellcheck: false
  }
});
```

### ۴.۳ سیاست «کاملاً آفلاین» (سه لایه)
```js
// لایهٔ 1: مسدودسازی همهٔ درخواست‌های http/https در کل نشست
session.defaultSession.webRequest.onBeforeRequest(
  { urls: ['http://*/*', 'https://*/*'] },
  (_d, cb) => cb({ cancel: true })
);
```
```js
// لایهٔ 2: ناوبری پنجره — هرگز داخل برنامه باز نشود
win.webContents.on('will-navigate', (e, url) => {
  if (!url.startsWith('file://')) { e.preventDefault(); if (/^https?:/) shell.openExternal(url); }
});
// لایهٔ 3: پنجره‌های جدید (target=_blank) → مرورگر سیستم
win.webContents.setWindowOpenHandler(({ url }) => {
  if (/^https?:/i.test(url)) shell.openExternal(url);
  return { action: 'deny' };
});
```
نتیجه: لینک «وب‌سایت» هر ورودی در مرورگر پیش‌فرض ویندوز باز می‌شود؛ خود برنامه هرگز به شبکه وصل نمی‌شود.

### ۴.۴ پل‌های IPC (پاسخ به `preload.js`)
| کانال | کار |
|---|---|
| `save-text-file` | دیالوگ بومی «ذخیره در…» ویندوز و نوشتن فایل پشتیبان JSON |
| `app-info` | برگرداندن `app.getVersion()` برای نمایش «نسخهٔ برنامه» |
| `app-hidden` (رویداد) | اعلان مینیمایز/پنهان‌شدن به رندرر برای قفل خودکار |

**چرا `app-hidden` لازم شد؟** باگ «رفتار برنامه»: در دسکتاپ، مینیمایز کردن پنجره رویداد `visibilitychange` صفحه را فعال نمی‌کند، پس «قفل هنگام غیرفعال شدن صفحه» هرگز اجرا نمی‌شد. حالا رویدادهای `minimize` و `hide` پنجره مستقیم به صفحه فرستاده می‌شوند:
```js
mainWindow.on('minimize', notifyHidden);
mainWindow.on('hide', notifyHidden);
```

### ۴.۵ ذخیرهٔ فایل پشتیبان
```js
ipcMain.handle('save-text-file', async (_e, payload) => {
  const result = await dialog.showSaveDialog(mainWindow, {
    defaultPath: path.join(app.getPath('downloads'), filename),
    filters: [{ name: 'JSON', extensions: ['json'] }]
  });
  if (result.canceled) return { ok: false, canceled: true };
  fs.writeFileSync(result.filePath, text, 'utf8');
  return { ok: true, path: result.filePath };
});
```
اگر کاربر «ذخیره» را لغو کند، HTML پیام «ذخیرهٔ فایل پشتیبان لغو شد.» نشان می‌دهد.

## ۵. `preload.js` — پل امن

```js
const { contextBridge, ipcRenderer } = require('electron');
contextBridge.exposeInMainWorld('electronAPI', {
  saveTextFile: (payload) => ipcRenderer.invoke('save-text-file', payload),
  getAppInfo: () => ipcRenderer.invoke('app-info'),
  onAppHidden: (callback) => ipcRenderer.on('app-hidden', callback)
});
```
به‌دلیل `contextIsolation: true`، صفحه فقط همین سه متد را می‌بیند — هیچ دسترسی مستقیمی به Node/فایل‌سیستم ندارد.

## ۶. `afterPack.js` — تزریق آیکون و متادیتا به exe

مشکل: ابزار استاندارد الکترون‌بیلدر (`rcedit-ia32.exe`) یک برنامهٔ ۳۲بیتی است که با wine فقط ۶۴بیتی اجرا نمی‌شود. راه‌حل ما:
1. `signAndEditExecutable: false` → الکترون‌بیلدر exe را ویرایش نمی‌کند.
2. هوک `afterPack` بعد از بسته‌بندی، `rcedit-x64.exe` را با wine اجرا می‌کند:
```js
execFileSync('wine', [rcedit, exePath,
  '--set-icon', 'resources/icon.ico',
  '--set-version-string', 'FileDescription', 'Offline Password Manager',
  '--set-version-string', 'ProductName', ...,
  '--set-file-version', '1.0.1', '--set-product-version', '1.0.1.0']);
```
3. اگر کش winCodeSign موجود نباشد (مثلاً محیط تازه)، هوک خودش آن را از اینترنت دانلود می‌کند (خودترمیم‌شونده).

خروجی بررسی‌شده: آیکون شما + «FileDescription/ProductName/CompanyName = Korosh and Luna» داخل exe تزریق می‌شود (آیکون در Taskbar و Explorer ویندوز دیده می‌شود).

## ۷. `app/Index.html` — هستهٔ برنامه (مشترک با اندروید)

توضیح ریزبه‌ریز ماژول‌های JS (رمزارز، دیتابیس، روتر و…) در سند اندروید (`توضیحات-کامل-کد.md` در زیپ اندروید) آمده است. اینجا خلاصه + نکات مخصوص ویندوز:

| ماژول | کار |
|---|---|
| `CryptoManager` | AES-256-GCM + PBKDF2-SHA-256 (۳۱۰هزار تکرار)، قالب Envelope |
| `DB` | IndexedDB با فالبک حافظه |
| `SettingsManager` | تنظیمات در localStorage + اعمال تم/قلم/انیمیشن |
| `PasswordGenerator/Strength` | تولید رمز امن + نوار قدرت |
| `VaultManager/BackupManager` | ساخت/باز/قفل گاوصندوق + پشتیبان‌گیری |
| روتر هش | `/dashboard`, `/search`, `/passwords/new`, `/passwords/:id`, `/generator`, `/categories`, `/settings`, `/backup`, `/restore`, `/about` |
| `renderAppShell` | ۷ تب: داشبورد، جستجو، تولید رمز، دسته‌ها، تنظیمات، پشتیبان، درباره (تب‌های تکراری «رمزها/علاقه‌مندی‌ها» حذف شدند؛ ایموجی تب‌ها در دسکتاپ مخفی است چون ویندوز 7 ایموجی ندارد) |

### نکات مخصوص ویندوز در HTML
- **نسخهٔ برنامه:** `renderVersionLine()` از `electronAPI.getAppInfo()` می‌خواند → «نسخهٔ برنامه: 1.0.1 (دسکتاپ)» در صفحهٔ «درباره» و پایین صفحهٔ قفل.
- **قفل هنگام مینیمایز:** `electronAPI.onAppHidden(...)` → `lockNow(true)`.
- **ذخیرهٔ پشتیبان:** `Utils.download()` اول `electronAPI.saveTextFile` را امتحان می‌کند (دیالوگ بومی) و در نبودش فالبک مرورگری دارد.
- **حداقل رمز اصلی: ۴ نویسه** (طبق درخواست کاربر؛ «1234» هم پذیرفته می‌شود).
- **فراموشی رمز عبور:** دکمهٔ قرمز در صفحهٔ ورود → دیالوگ تأیید → `DB.deleteItem('vault')` → شروع از اول.
- **تم تیره:** کنترل‌های فرم (چک‌باکس/رادیو/اسلایدر/سلکت) کاملاً اختصاصی‌اند + `color-scheme` برای منوهای بومی — دیگر «خط سفید» در تم تیره وجود ندارد.
- **سازگاری Chromium 108:** هیچ `color-mix()` در CSS نیست (ریشهٔ باگ دکمه‌های سفید).

## ۹. خطای «NSIS Error: Installer integrity check has failed» — تحلیل کامل

**این خطا یعنی فایل نصب‌کننده هنگام دانلود/انتقال ناقص یا خراب شده است** (متن خود NSIS هم همین را می‌گوید: «incomplete download and damaged media»).

تحلیلی که برای اطمینان انجام شد:
- ساختار NSIS فایل ما استخراج و اعتبارسنجی شد: `siginfo=0xDEADBEEF` ✓، طول‌های هدر با اندازهٔ فایل دقیقاً هم‌خوان ✓.
- با سورس رسمی NSIS 3.0.4 (تابع `loadHeaders` در `Source/exehead/fileform.c`) مشخص شد که این پیام در چند مسیر صادر می‌شود — از جمله وقتی فایل روی دیسک از `length_of_all_following_data` هدر **کوتاه‌تر** باشد؛ یعنی دقیقاً حالت دانلود ناقص.
- یک نصب‌کنندهٔ سالمِ مرجع که با همین electron-builder ساخته شده (Sleek) دانلود و بایت‌به‌بایت مقایسه شد: **الگوی هدر و CRC هر دو دقیقاً یکسان‌اند** → فایل ما ساختاراً سالم است.

**راه‌حل‌ها:**
1. **نسخهٔ قابل حمل (توصیهٔ اول):** `OfflinePasswordManager-Portable-1.0.1-x64.zip` — بدون نصب‌کننده؛ فقط استخراج و اجرا. هیچ بررسی NSISای در کار نیست.
2. **دانلود مجدد نصب‌کننده** و راستی‌آزمایی:
   - اندازهٔ فایل باید دقیقاً **۶۹٬۰۴۳٬۷۱۳ بایت** باشد (کوچک‌تر = ناقص).
   - در cmd: `certutil -hashfile "OfflinePasswordManager-Setup-1.0.1-x64.exe" SHA256` و مقایسه با هش انتهای همین سند.
3. اگر دوباره خطا آمد: مرورگر/دانلودمنیجر دیگری امتحان کنید (خطا مربوط به انتقال فایل است، نه فایل).

> هشدار SmartScreen («Windows protected your PC») چیز دیگری است و طبیعی — چون برنامه امضای دیجیتال ندارد؛ با **More info → Run anyway** ادامه می‌دهید.

## ۱۰. بیلد و توسعه

### پیش‌نیازها (بیلد ویندوزی روی لینوکس)
- Node.js 20+، wine (۶۴ و ۳۲ بیتی)، Xvfb، p7zip

### دستورها
```bash
npm install                 # electron 22.3.27 + electron-builder
npm start                   # اجرای برنامه (روی لینوکس: xvfb-run -a npm start)
npm run dist                # نصب‌کنندهٔ NSIS در release/
# نسخهٔ قابل حمل = محتوای release/win-unpacked/ (زیپ شود)
```

### تست‌ها (روی لینوکس با Xvfb)
```bash
xvfb-run -a npx electron test-smoke.js --no-sandbox     # فلو اصلی
xvfb-run -a npx electron test-visual.js --no-sandbox    # صحت بصری پیکسل‌به‌پیکسل
xvfb-run -a npx electron test-bugs.js --no-sandbox      # رگرسیون ۲۵ مرحله‌ای
xvfb-run -a npx electron test-android.js --no-sandbox   # شبیه‌سازی موبایل
```
هارنس‌ها با اجرای واقعی Electron 22 (= همان Chromium ویندوز) رفتار برنامه را بررسی می‌کنند: رنگ کامپیوت‌شدهٔ دکمه‌ها، موقعیت تب‌ها، وجود متن‌ها، رمزگشایی پشتیبان با Node/webcrypto و حتی تحلیل پیکسلی اسکرین‌شات‌ها.

### نکات ریز بیلد
- بعد از `npm install`، در پوشهٔ `release/` ابتدا `win-unpacked/` (نسخهٔ قابل حمل) و سپس نصب‌کننده ساخته می‌شود.
- اگر `afterPack` گزارش دهد rcedit نیست، خودش winCodeSign را دانلود می‌کند.
- بیلد روی ویندوز بومی هم با `npm run dist` بدون هیچ تغییری کار می‌کند (wine لازم نیست).
